# Личный дневник диабета

Реализована задача 01: единственный аккаунт, вход и выход, независимые сессии устройств. Записи и расписания появятся в следующих задачах.

## Локальный запуск

Проверено: Windows, Python 3.12.14, Node.js 22.19.0, npm 11.11.1. Нужны Python 3.12 или 3.13, Node.js от 22.12 и [uv](https://docs.astral.sh/uv/). Точные версии Python-пакетов и npm-пакетов сохранены в `uv.lock` и `frontend/package-lock.json`.

Из корня репозитория в PowerShell:

```powershell
uv sync --frozen --python 3.12
uv run --frozen python -m diary.admin --database data/diary.sqlite3 migrate
uv run --frozen python -m diary.admin --database data/diary.sqlite3 create-account --login owner
```

Введите пароль дважды в интерактивном терминале. Ввод скрыт; длина 15–1024 символа, вставка разрешена. Пароль не передаётся флагом или переменной окружения. При недоступном скрытом вводе команда отказывает. Повторное создание аккаунта отклоняется.

В первом терминале из корня:

```powershell
$env:DIARY_DATABASE = "$PWD/data/diary.sqlite3"
$env:DIARY_ORIGIN = "https://localhost:5173"
uv run --frozen uvicorn diary.app:from_env --factory --host 127.0.0.1 --port 8000 --no-proxy-headers --no-access-log
```

Во втором терминале:

```powershell
cd frontend
npm ci
npm run dev
```

Откройте **https://localhost:5173**. Vite создаёт локальный самоподписанный сертификат; для разработки подтвердите исключение браузера. API доступен через прокси Vite с тем же origin. Cookie всегда `Secure`, `HttpOnly`, `SameSite=Lax`, с префиксом `__Host-`, без `Domain`; HTTP-режима с ослабленной cookie нет.

В Linux/macOS используются те же команды; вместо PowerShell-присваивания: `export DIARY_DATABASE=/absolute/path/diary.sqlite3` и `export DIARY_ORIGIN=https://localhost:5173`.

Для проверки с телефона в доверенной локальной сети укажите в `DIARY_ORIGIN` точный HTTPS-адрес компьютера, например `https://192.168.1.10:5173`, перезапустите API и запустите `npm run dev -- --host 0.0.0.0`. Телефон открывает этот адрес с подтверждением локального сертификата. Это сервер разработки для локальной проверки. Фактический iPhone/Safari ещё не проверен.

SQLite создаётся только командой миграции. Приложение не создаёт схему при старте. Перезапуск и повтор `migrate` сохраняют данные. Для реального использования путь к БД должен быть на постоянном локальном диске вне релизов и публичной статики, с правами только для пользователя сервиса; локальные `data/`, сертификаты, `.env` и файлы SQLite исключены из Git.

## Смена пароля и отзыв сессий

В отдельном терминале, пока API запущен:

```powershell
uv run --frozen python -m diary.admin --database data/diary.sqlite3 reset-password
```

Новый хеш и удаление всех сессий фиксируются одной транзакцией. Неудачная операция откатывается. Для проверки:

1. Войдите в двух браузерах или на телефоне и компьютере.
2. Выйдите на одном устройстве: второе сохраняет вход.
3. Снова войдите на обоих и выполните `reset-password`.
4. В каждом браузере обновите страницу: старые cookie получают 401, появляется форма входа. Старый пароль отклоняется, новый позволяет войти.

После пяти ошибок за 15 минут блокируются новые проверки пароля по источнику **или** логину. Отказ 429 с `Retry-After: 900` не продлевает блокировку; после выхода ошибок из скользящего окна вход доступен. Счётчики хранятся в SQLite. Неизвестный логин и неверный пароль дают одинаковый ответ.

## API и общая защита

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/auth/csrf` | Получить `{csrf_token}` для текущей сессии либо предварительную cookie на 15 минут. |
| `POST /api/auth/login` | JSON `{login, password}`; возвращает `{login, csrf_token}` и новую cookie на 30 дней. Логин: 1–128 символов после удаления крайних пробелов; пароль: до 1024 символов, без преобразования. |
| `GET /api/auth/session` | `{login}` для действующей сессии; иначе 401. |
| `POST /api/auth/logout` | Отозвать текущую сессию; 204 и удаление cookie. |

Для POST обязательны точный `Origin` и `X-CSRF-Token`, полученный через `/csrf`. Предварительный токен после входа недействителен; новый связан с новой сессией. Значения сессий и предварительных cookie случайны (32 байта), в БД только SHA-256. CSRF получается из случайного токена с отдельным префиксом. Серверный срок сессии фиксирован от входа и не продлевается чтением. Повторный вход отзывает прежнюю сессию этого устройства.

Весь FastAPI защищён middleware по умолчанию. Исключения — только точные пары метода и пути `/csrf` и `/login`. Новые предметные маршруты автоматически требуют сессию и для изменений Origin/CSRF. Не создавайте отдельный незащищённый API. Публичная статика не содержит данных владельца. CORS не включён; документация `/docs`, `/redoc`, `/openapi.json` отключена во всех окружениях.

Ответы имеют `Cache-Control: no-store`. Ошибки: `{code, message, field}` без введённых значений; статусы 401, 403, 422, 429, 503, а также 400 для неверного Host и 413 для тела свыше 64 КиБ. SQLite использует внешние ключи, `synchronous=FULL`, ожидание блокировки до 10 секунд. Вход и восстановление пароля сериализованы `BEGIN IMMEDIATE`. Ошибка БД не объявляется успехом. Тела запросов, пароли, cookie и SQL-параметры не журналируются; access-log Uvicorn отключён в инструкции.

## Проверки

```powershell
uv run --frozen pytest
uv run --frozen mypy
cd frontend
npm ci
npm run build
npx playwright install chromium --only-shell
npm run test:e2e
```

HTTP-тесты используют временные файловые SQLite, реальные миграции и Argon2id. Часы подменяются только для проверки точных границ сроков. Проверяются перезапуск, повтор миграции, ротация, выход, смена пароля, CSRF/Origin, общий запрет доступа, ограничения по IP и логину, поддельный `X-Forwarded-For` и одновременные попытки.

Playwright сам запускает API с одноразовой SQLite и синтетическим аккаунтом, а также HTTPS Vite. Порты 8000 и 5173 должны быть свободны. Сценарий выполняется в Chromium для настольного и мобильного размеров: вход, перезагрузка, выход с клавиатуры, повторная перезагрузка; проверяет cookie и отсутствие localStorage. Это эмуляция размера экрана, не проверка Safari или реального iPhone. Скриншоты, видео и трассировка с секретами не сохраняются.

## Production

`npm run build` создаёт `frontend/dist`. Отдавайте только этот каталог через HTTPS-веб-сервер; `/api/*` проксируйте на закрытый `127.0.0.1:8000` с исходным Host. `DIARY_ORIGIN` — точный внешний HTTPS-origin без завершающего `/`. Не публикуйте порт Uvicorn. Для проверенного локального обратного прокси Uvicorn допускает `--proxy-headers --forwarded-allow-ips 127.0.0.1`; сам прокси должен заменять непроверенные заголовки адреса. Без проверенного прокси оставьте `--no-proxy-headers` (источник тогда общий для запросов прокси). Не используйте доверие ко всем адресам `*`.

VPS, домен, системный сервис, права файлов, HTTPS и резервирование здесь не настроены и относятся к следующим задачам. Перед первыми реальными данными нужны внешние копии и проверенное восстановление согласно спецификации. До будущих миграций существующей рабочей БД необходим проверенный согласованный снимок; текущая миграция только создаёт первую схему.
