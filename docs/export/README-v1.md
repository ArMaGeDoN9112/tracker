# Полный JSON-экспорт, версия 1

В настройках выберите «Экспорт всех данных». `GET /api/export` проверяет текущую
сессию и отдаёт UTF-8 JSON непосредственно как attachment с именем
`diabetes-diary-<unix_ms>.json` (момент экспорта в миллисекундах Unix), `Content-Type: application/json` и
`Cache-Control: no-store`. Публичная ссылка и файл на сервере не создаются.
При истёкшей или отозванной сессии возвращается 401 без файла; войдите снова.
Файл содержит личные сведения, включая мягко удалённые данные. Храните его приватно.

Все выборки выполняются внутри одного снимка SQLite, установленного первым чтением
аккаунта после явного BEGIN. `exported_at` — серверное время сразу после установки
снимка, а не время завершения скачивания. Конкурентные изменения целиком окажутся
до снимка либо после него; состояния разных моментов не смешиваются. Параметры дня,
периода и страницы не применяются. Ограничений возраста и количества записей нет.
Сборка файла использует память пропорционально размеру всей истории.

Машиночитаемый контракт: [schema-v1.json](schema-v1.json), JSON Schema draft 2020-12.
Синтетический валидный пример: [example-v1.json](example-v1.json).
Все перечисленные поля присутствуют, неизвестность передаётся явным `null`.
Несовместимое изменение типа, смысла, единиц, удаления/добавления обязательных полей
увеличивает целый `schema_version`; схема и пример прежней версии сохраняются.
Потребитель должен проверять версию перед чтением. Новые необязательные поля также
требуют новой версии, поскольку схема v1 запрещает неизвестные свойства.

## Корень и единицы

| Поле | Значение |
| --- | --- |
| `schema_version` | Целое 1, версия этого формата, независимо от миграций БД. |
| `exported_at` | Время снимка, RFC 3339 UTC с миллисекундами. |
| `timezone` | `Europe/Moscow`, зона календарных дней и интервалов расписания. Исторические смещения берутся из IANA, это не постоянное UTC+3. |
| `units` | Единицы и точность значений, описанные ниже. |
| `settings` | Все настройки первой версии: `timezone: Europe/Moscow`, `theme: dark`. Они фиксированы приложением, отдельных пользовательских настроек в БД нет. |
| `account` | Несекретные `id` (целое 1), `login` (Unicode-строка), `created_at` (время создания). |
| `entries` | Все записи, включая удалённые; порядок: время события, создания, UUID по возрастанию. |
| `basal_schedules` | Все полные версии расписания по возрастанию начала. |
| `temporary_basals` | Все временные базы, включая удалённые; порядок: начало, создание, UUID. |

`units.timestamps = RFC 3339 UTC, milliseconds`: все времена — строки RFC 3339
в UTC с явным смещением `Z` и тремя знаками миллисекунд, например
`1970-01-01T00:00:00.123Z`. Даты до Unix-эпохи также поддерживаются. Точность не теряется,
смещение устройства не влияет.
Для отображения московского времени используйте `Europe/Moscow`.

`units.glucose = mmol/L`: строка `"5.6"` означает 5,6 ммоль/л, всегда один знак после точки.
`units.bolus = U`: строка `"1.2"` означает 1,2 единицы инсулина, всегда один знак.
`units.rate = U/h`: строка `"0.55"` означает 0,55 ед/ч, всегда два знака.
`units.duration_minutes = minute`: длительность в целых минутах.
`units.percent = percent`: целые проценты, 120 означает множитель 1,2.
`units.minute = minute of Moscow day`: минута местных суток от полуночи, 0–1439.
Десятичные значения передаются строками без двоичного float. Для независимых расчётов используйте
целые числа или десятичную арифметику.

## Запись (`entries`)

| Поле | Значение |
| --- | --- |
| `id` | Сохранённый UUID строкой; не заменяется при правке/удалении. |
| `occurred_at` | Фактическое время события с точностью до миллисекунды. |
| `glucose` | Десятичная строка ммоль/л: `"0.1"`–`"214748364.7"`, либо `null`, если измерения нет. |
| `bolus` | Десятичная строка единиц: `"0.0"`–`"214748364.7"`; `"0.0"` означает отсутствие подколки. |
| `reason` | `food` — еда, `correction` — коррекция, `food_and_correction` — еда и коррекция; `null` — не указана. При нулевой подколке всегда `null`. |
| `comment` | Unicode-текст до 10000 символов, включая переводы строк; пустая строка допустима. Это текст, не HTML. |
| `created_at` | Время создания в сервисе, не обязательно время события. |
| `updated_at` | Время последней правки, удаления или восстановления. |
| `revision` | Положительная текущая редакция, начинается с 1 и растёт при изменении. |
| `deleted_at` | Время мягкого удаления либо `null` у неудалённой записи. |

Это актуальное содержимое каждой записи с её редакцией; прежние значения всех
правок не хранятся. Удалённые записи сохраняются бессрочно, но исключаются из
дня и сводок. Восстановление убирает `deleted_at` и увеличивает редакцию.
Вычисленная база не копируется в запись: её можно проверить по расписаниям и
временным базам этого же снимка. Неизвестная база до первого расписания — `null`,
нулевая известная скорость — `"0.00"`; эти состояния различны.

## Версия расписания (`basal_schedules`)

`id` — UUID, `starts_at` — включённое начало, `ends_at` — исключённое начало
следующей версии либо `null` без ограничения конца, `created_at` — время создания.
Версии неизменяемы: у них нет редакции, времени изменения и удаления.
`intervals` — полное расписание, элементы `{minute, rate}`; `minute` — минута
московских суток 0–1439, `rate` — десятичная строка ед/ч `"0.00"`–`"21474836.47"`.
Первый интервал начинается в 0; последующие начала строго возрастают.
Интервал действует от своего начала включительно до следующего исключительно,
последний — до следующей местной полуночи, с учётом границы версии расписания.
Версии действуют на полуоткрытых промежутках `[starts_at, ends_at)`.

## Временная база (`temporary_basals`)

`id` — UUID; `starts_at` — включённое начало; `ends_at` — заданное исключённое
окончание (может совпадать с началом для нулевого периода).
`duration_minutes` — исходная длительность при создании, 1–2147483647 минут;
при изменении начала/окончания она сохраняется и не обязана равняться их разности.
`percent` — целый процент 0–2147483647.
`created_at`, `updated_at`, `revision`, `deleted_at` имеют тот же смысл, что у записей.

`effective_ends_at` — производное окончание: минимум заданного `ends_at` и начала
следующей **неудалённой** временной базы; без следующей — заданное окончание.
У удалённой временной базы `effective_ends_at = null`: она не действует и не обрезает
соседей. При совпадении начал удалённые строки игнорируются. Новая временная база
прекращает предыдущую без последующего возобновления; проценты не складываются.
Удаление и восстановление пересчитывают производные окончания соседей при чтении,
не переписывая их заданные окончания.

В момент `t` выберите неудалённый период `starts_at <= t < effective_ends_at`.
Его процент применяется к интервалу действующей в `t` версии расписания, включая
переходы московской полуночи и смену версий. Округление до сотых half-up:
для целой скорости `rate` в сотых результат в сотых равен
`(rate * percent + 50) // 100`. Например, 55 × 110% даёт 61 (0,61 ед/ч).
Если период не действует, берите обычную скорость. Неизвестная скорость остаётся
`null` при любом проценте, включая 0%. Расчётная скорость может превышать предел
хранимой скорости — вычисляйте произведение без переполнения. Это значение
«по расписанию», оно не подтверждает фактическую подачу помпы.

## Что не включено

Хеши паролей, сессии, CSRF, ключи резервирования, квитанции операций, журналы
и технические счётчики не экспортируются. Отсутствующие предметные каталоги
не создаются. Пользовательского импорта нет; восстановление сервиса выполняется
из резервной копии, а JSON служит для независимой проверки и переноса данных.

На финальной приёмке откройте настройки на реальном iPhone/Safari и компьютере,
скачайте файл, проверьте имя `.json`, чтение UTF-8/Unicode и наличие старой удалённой
записи. Автоматические браузерные проверки используют Chromium, включая размер iPhone.
