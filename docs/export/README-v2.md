# Полный JSON-экспорт, версия 2

В настройках выберите «Экспорт всех данных». `GET /api/export` проверяет текущую
сессию и отдаёт UTF-8 JSON как attachment `diabetes-diary-<unix_ms>.json`,
`Content-Type: application/json`, `Cache-Control: no-store`. Файл содержит личные
сведения, включая архивные и мягко удалённые данные; храните его приватно.
Истёкшая или отозванная сессия получает 401 без файла. После входа скачивание
нужно повторить явно. Публичная ссылка и файл на сервере не создаются.

Контракт: [schema-v2.json](schema-v2.json), JSON Schema draft 2020-12;
[синтетический пример v2](example-v2.json). Схема генерируется из `FullExport`
в `diary/interfaces/export.py`; тест сравнивает её с DTO и проверяет пример обоими способами.
Сохранены [описание v1](README-v1.md), [схема v1](schema-v1.json) и
[пример v1](example-v1.json). Endpoint выдаёт только v2; JSON-импорта нет.

Все сущности читаются в одном явном `BEGIN`, снимок устанавливает первое чтение
аккаунта. `exported_at` — время сразу после установки снимка, до сборки файла.
Конкурентные изменения карточки/порций, приёмов/строк и настроек не смешиваются.
Параметры дня, периода и страницы не ограничивают выгрузку. Память и размер файла
пропорциональны всей истории; ограничений возраста и количества записей нет.

## Корень

Поля `exported_at`, `timezone`, `account`, `entries`, `basal_schedules` и
`temporary_basals` сохраняют [смысл версии 1](README-v1.md). `schema_version`
теперь равен 2 и не связан с номером миграции БД. Все времена — RFC 3339 UTC
с тремя знаками миллисекунд. Календарные дни отображаются в `Europe/Moscow`.

| Поле v2 | Содержимое |
| --- | --- |
| `products` | Все актуальные карточки, включая архивные, со всеми текущими порциями. Порядок: создание, UUID. |
| `meals` | Все приёмы со строками и расчётами, включая мягко удалённые. Порядок: событие, создание, UUID. |
| `water` | Все явно внесённые события воды, включая мягко удалённые. Тот же порядок, что у приёмов. |
| `settings` | Прежние `timezone`, `theme` и `water: {volumes_ml, revision}` — общие кнопки воды в пользовательском порядке, включая допустимый пустой набор. |
| `units` | Прежние единицы плюс `food_quantity: g or ml; see unit`, `nutrients: g per basis_quantity`, `calories: kcal per basis_quantity`, `water: integer ml`. |

## Каталог и самостоятельная история

Карточки совпадают с ответом [API каталога](../nutrition-api.md): `id`, `name`,
`unit` (`g`/`ml`), независимые `protein`, `fat`, `carbohydrate`, `calories` на
**100** г/мл, `archived`, `revision`, `created_at`, `updated_at`, `portions`.
Порция содержит устойчивый `id`, `name`, `quantity` в единице карточки;
порядок массива сохранён. Редакция и временные поля относятся ко всей карточке
с порциями. Прежние редакции каталога не ведутся отдельным журналом.
Необязательное `photo` — JPEG-миниатюра в data URL либо `null`; старые
экспорты v2 без этого поля остаются допустимыми. Фотографии не копируются
в исторические строки приёмов.

Приём содержит `id`, `occurred_at`, `category` (либо `null`), `revision`,
`created_at`, `updated_at`, `deleted_at`, упорядоченные `lines` и `totals`.
Каждая строка хранит собственные `id`, `kind`, `name`, `unit`, `quantity`,
`basis_quantity`, четыре исходных показателя, `product_id`, `product_revision`,
историческую `portion` и вычисленные `totals`. Происхождение продукта — справочная
информация, не зависимость расчёта от актуальной карточки или порции.
После смены единицы/архива/порций каталога старые основы сохраняются.

Количество, основы, БЖУ (г) и энергия (ккал) представлены десятичными строками
с двумя знаками, без двоичного float. `null` означает неизвестность; `"0.00"` —
известный ноль. Калории с этикетки не выводятся из БЖУ. У строки продукта основа
`"100.00"`; у разовой еды — исходное съеденное количество или `null`, если оно
неизвестно. При неизвестной основе показатели относятся ко всей исходной порции,
новый вес сам по себе их не масштабирует. Разовая еда не имеет происхождения
из каталога. Мягкое удаление приёма сохраняет весь состав бессрочно.

Для независимого расчёта известный вклад равен
`показатель × quantity / basis_quantity`, если обе величины известны;
при неизвестной основе берётся исходный показатель целиком. Суммируйте точные
вклады и округляйте half-up до сотых только при выводе каждого результата.
Например, две строки по 50 г с 0,01 г на 100 г дают суммарно 0,01 г,
хотя каждая строка отдельно выводит 0,01 г. `totals` приёма содержит для каждого
показателя `value`, `known_count`, `unknown_count`, `incomplete`. Пустое множество
известных вкладов даёт `value: null`. Для повторного расчёта каталог не нужен.

Вода содержит `id`, целое положительное `volume_ml`, `occurred_at`, `revision`,
`created_at`, `updated_at`, `deleted_at`. Объёмы еды в мл автоматически водой
не становятся. Настройки кнопок не переписывают историю.

## Приватность и восстановление

Хеши паролей, сессии, CSRF, ключи, технические квитанции, логи и счётчики
не экспортируются. JSON предназначен для независимого чтения и переноса.
Сервис восстанавливается из [зашифрованной SQLite-копии](../backup.md), включая
служебные данные, с отзывом восстановленных сессий. Новый релиз проверяет всю
схему `008_water`; предмиграционная копия старой схемы проверяется совместимым
старым релизом. Номер JSON-формата и формат restic manifest независимы.
