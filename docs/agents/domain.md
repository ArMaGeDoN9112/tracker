# Domain docs

This repo uses a single context.

## Before exploring

- Read root `GLOSSARY.md` if present.
- Read relevant decisions in `docs/adr/` if present.

If these documents are absent, proceed silently.
The domain-modeling skill creates them as terms and decisions
are resolved.

## Vocabulary

Use terms defined in the glossary in issues, proposals, and tests.
Reconsider invented synonyms; note real gaps for domain-modeling.

## Decision conflicts

Explicitly flag any proposal that contradicts an existing ADR,
identify the ADR, and explain why it should be reconsidered.
