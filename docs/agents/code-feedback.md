# Замечания пользователя по коду

Перед изменением или ревью кода применяй относящиеся к задаче правила ниже.
При новом замечании пользователя обновляй соответствующее правило или добавляй новое
в рамках той же задачи. Записывай согласованный подход и конкретный пример;
собственные предположения не выдавай за предпочтения пользователя.
Если пользователь меняет решение, замени прежнее правило, сохраняя документ актуальным.

## SQLAlchemy

Используй SQLAlchemy Core: `select`, `insert(...).values(...)`, `update`, `delete`.
Описания таблиц переиспользуй из `diary/tables.py`.
Служебные команды SQLite `PRAGMA`, `BEGIN` и `BEGIN IMMEDIATE` сохраняй там,
где они обеспечивают настройки и нужную семантику транзакций.

Основание: пользователь попросил заменить голый SQL вызовами SQLAlchemy
и привёл пример `insert(user_table).values(...)`.

## DTO

Для данных между функциями и ответов API используй конкретные типизированные DTO
на Pydantic с доступом через атрибуты. Переиспользуй существующие модели запросов,
ответов и внутренние DTO; указывай конкретные возвращаемые типы.
Словари уместны на границах SQL/JSON, в таблицах соответствий и протоколе ASGI.

Основание: «постарайся везде использовать специальные DTO вместо словарей».

## Enum для действий

Для фиксированного набора действий используй enum в аргументах, сравнениях и DTO.
Пример: `change_entry(OperationAction.RESTORE_ENTRY, payload, entry_id)`.
Существующий `OperationAction` основан на `StrEnum`; сохраняй строковые значения
при записи в БД и сериализации API, чтобы прежние данные и клиенты оставались совместимыми.

Основание: пользователь указал на `change_entry("restore_entry", ...)`
и попросил использовать enum.

## Асинхронные контекстные менеджеры

Для функции с `@asynccontextmanager` указывай `AsyncGenerator`,
например `async def lifespan(...) -> AsyncGenerator[None]`.

Основание: пользователь сообщил предупреждение об устаревшей аннотации `AsyncIterator`
для этого декоратора.
