## Decisions-so-far

- Календарь становится главной страницей.
- Верхний уровень включает самостоятельные разделы «Диабет» и «Питание».
- Ввод и анализ разделены на разные страницы внутри разделов.
- На странице ввода сахара нет хронологии.
- Календарь показывает дневные итоги и графики по времени вместо списка записей.
- Вода в календаре показана общим объёмом за день.
- Питание показывается графиком по времени дня.
- «Диабет» и «Питание» открываются на странице «Ввод», «Анализ» — отдельная страница.
- В «Диабете» также находится «База», в «Питании» — «Каталог» и учёт воды.
- «Настройки» — общий служебный пункт.
- При открытии календаря сразу показана сводка сегодня.
- КБЖУ одновременно показаны разными цветами на одном графике питания;
  численные значения доступны при наведении на время или точку.
- Сахар и подколки — точки с линиями на двух графиках друг под другом
  с общей временной шкалой и разными единицами; ниже остаётся график базы.
- Управление отдельными записями находится в «Анализе» выбранного раздела
  с выбором дня; календарь даёт переход к записям своего выбранного дня.
- Подсказки графиков работают при наведении мыши и касании/перемещении пальца;
  сахар и подколки синхронно подсвечивают выбранное время.
- Сохранение новой записи оставляет пользователя на вводе с подтверждением.
- Исправление выполняется в «Анализе», повтор еды открывает заполненную форму во «Вводе».
- По последующему решению пользователя сохранение и восстановление черновиков
  полностью удаляются. Уход со страницы ввода/исправления, выход, истечение сессии
  и перезагрузка сбрасывают несохранённые значения; возврат их не восстанавливает.
- Шаг выбора продукта в текущем приёме сохраняет его состав до завершения сценария.
  Защита операций от дубликатов, проверка редакций и отмена удаления сохраняются.
- Пользователь подтвердил итоговую структуру и поведение перед реализацией.
- Полная спецификация оформлена через to-spec; основной уровень проверки —
  существующие браузерные тесты Playwright с настоящим тестовым API на компьютере
  и телефоне, отдельно согласован с пользователем.
- Пользователь согласовал крупность и зависимости шести задач; каждая опубликована
  отдельным тикетом со статусом ready-for-agent. Первой выполняется
  [01 — удаление обработки черновиков во всех разделах](issues/01-remove-drafts.md).
- Зависимости: 01 → 02; 02 → 03 и 04; 03 → 05; 04 → 06.

- 27.10.2026: [тикет 01 завершён](issues/01-remove-drafts.md#answer). Все формы
  сбрасываются при уходе и повторном входе; шаги выбора/создания продукта внутри
  текущего приёма сохраняют состав. Удержанные запросы сохраняют UUID, тело, метод
  и адрес независимо от формы; повтор остаётся явным. Конфликты в открытой форме
  и глобальная отмена с исходным сроком сохранены. Поздние ответы не возвращают
  закрытые формы. Скрытый дневник не загружает форму и не вычисляет базу.
- Приёмка 01: TypeScript и сборка успешны, полный Playwright — 168 passed
  (84 desktop + 84 phone с настоящим тестовым API), полный pytest — 469 passed.
  Ревью Standards / Spec — по 0 открытых замечаний. Контракты API, схема БД
  и зависимости сохранены. Обновлены README и docs/diabetes-diary.md.
