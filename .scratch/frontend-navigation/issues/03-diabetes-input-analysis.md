# 03: Разделить ввод и анализ диабета

Status: resolved
Type: task
Blocked by: 02

**What to build:** пользователь добавляет сахар/подколку на странице ввода без
хронологии, а в анализе выбирает день, просматривает записи, исправляет и удаляет их.

## Acceptance criteria

- [x] Ввод содержит форму без истории; сохранение оставляет на вводе с подтверждением.
- [x] Анализ сохраняет аналитику за период и даёт доступ к записям выбранного дня,
  исправлению рядом со списком, удалению и отмене удаления.
- [x] Выбор дня в периодической аналитике открывает записи внутри анализа.
  Из диабетической части календаря можно перейти в анализ того же дня.
- [x] Сохраняются ввод только сахара, только подколки, комментария, изменение даты
  записи, значения базы и различие между временем события и временем создания.
- [x] Конфликты редакций, проверка актуальной записи, ошибки, явные повторы запросов
  и серверный срок глобальной отмены проверены после переноса.
- [x] Уход с ввода или исправления сбрасывает несохранённые значения; входы
  и навигация не восстанавливают их и не отправляют операции автоматически.
- [x] Даты периода, московское время, загрузка при открытии и прежние расчёты сохранены.

- [x] Пройдены проверка типов, сборка и относящиеся к сценарию существующие браузерные проверки с настоящим тестовым API на компьютере и телефоне.
- [x] Документация текущего поведения обновлена; схема БД и контракты API сохранены, новые зависимости не добавлены.

## Общие ограничения

- Переиспользовать существующие операции и компоненты. Сохранить проверку редакций, защиту от дубликатов, явный повтор неизвестного запроса и глобальную отмену удаления с исходным серверным сроком.
- Черновики не сохраняются и не восстанавливаются между страницами или входами. Состав текущего приёма при выборе продукта внутри того же сценария не теряется.
- Данные загружаются при открытии страницы и после её собственных изменений, без фонового опроса и кнопок обновления. Время — HH:MM, расчёты — по Москве.
- До входа личные данные скрыты. Навигация и повторный вход не отправляют операции автоматически.
- Полные требования и согласованные проверки: [спецификация](../spec.md).

## Answer

Перед началом проверен тикет 02: `Status: resolved`, его изменения находятся
в исходном HEAD текущей ветки `master` — `b807558`. Рабочее дерево было чистым.

Ввод диабета содержит только существующую форму создания. Сохранение оставляет
пользователя на вводе с подтверждением. Хронология, выбор дня, исправление,
удаление и отмена удаления перенесены в анализ вместе с прежними операциями.
Аналитика за период сохраняет две даты и прежние расчёты; выбор дня открывает
его записи внутри анализа. Ссылка «Записи диабета» из календаря открывает
анализ того же дня через SPA-навигацию, сохраняя глобальную отмену и удержанные
запросы; обычные ссылки с модификаторами и новая вкладка продолжают работать.

Исправление находится рядом со списком на компьютере и перед ним на телефоне.
Смена дня, уход, история браузера и повторный вход сбрасывают несохранённые
значения. Подтверждённый перенос записи на другую дату сохраняет уведомление
об успехе. Поздний конфликт закрытого редактора не возвращает панель сравнения.
Ошибки и повтор подключения доступны в анализе; выбор известного дня не зависит
от успешной загрузки начальной формы. В хронологии отдельно показано время
создания, исходное время события и его точность сохраняются.
