# 01: Локальная проверка восстановления

**What to build:** локально подтвердить готовность механизма регулярной проверки
восстановления и отображения его результата. Проверка настоящего внешнего
хранилища и установка расписания на VPS остаются задачей 04.

**Blocked by:** None (can start immediately). Механизм уже реализован.

**Status:** resolved

**Type:** task

- [x] Реализовано изолированное восстановление последней подтверждённой точки,
  проверка целостности, схемы, контрольных данных и чтения приложением без замены
  рабочей БД. Недельный шаблон запуска подготовлен; установка на VPS — задача 04.
- [x] Команда `verify` выполняет `restic check --read-data`, восстановление и проверку
  снимка. Ошибки не объявляются успешным восстановлением.
- [x] В настройках различаются успех восстановления, ошибка и просрочка 26 часов;
  сбой не обновляет время успеха. Проверены неизвестное состояние после ошибки
  чтения и защита от запоздавшего прежнего успеха.
- [x] Системные service/timer не зависят от посещения приложения; инструкция
  описывает повтор учения после изменения схемы и проверку фактической установки.
- [x] Синтетические проверки с настоящим локальным restic покрывают восстановление,
  отзыв сессий, чтение истории, успешный/неуспешный verify и сохранность исходной БД.
  При добавлении сущностей контрольные данные расширяются вместе со схемой.
- [x] Ограничения внешних уведомлений, времени восстановления и локального прогона
  явно описаны. Внешняя доставка и реальная недельная периодичность не заявлены проверенными.

## Answer

20 октября 2026. Повторная реализация не нужна: механизм уже входит в
`diary/backup.py`, `ops/diary-verify.service`, `ops/diary-verify.timer` и интерфейс статуса.
Код, схема, зависимости и рабочие данные в этой задаче не менялись.

- `pytest -q -p no:cacheprovider tests/test_backup.py` — **8 passed**, 147,88 с,
  в `tracker-checks` с текущими исходниками/тестами/миграциями, подключёнными только
  для чтения. Настоящий зашифрованный restic, одноразовая файловая SQLite,
  без сети, опубликованных портов и рабочих томов.
- `playwright test backup.spec.ts` — **6 passed**, 8,6 с, desktop/phone Chromium,
  в `diary-layout-a-impl-e2e` с текущими исходниками. Используется тестовый API
  и синтетическая БД; варианты статуса резервирования подменяются только на HTTP-границе.
- Восстановленный экспорт, день и сводка совпадают со снимком; позднейшие записи
  исходной БД не потеряны. Проверены ключ/недоступность репозитория, ротация семи
  дней, pending при испорченной обратной загрузке, параллельный запуск и ошибки статуса.
- Начальный запуск не завершился из-за остановки Docker; приведённые результаты
  относятся к полному повторному прогону, а не к прерванному запуску.
- Есть предупреждение Starlette об устаревающем сочетании TestClient/httpx;
  обновление зависимостей в уборку документов не включалось.

Это закрывает локальную программную часть прежней задачи 10. Внешний репозиторий,
недельный запуск на реальном сервере, его перезагрузка и реальный iPhone здесь
не проверялись. Допуска к реальным данным нет.
