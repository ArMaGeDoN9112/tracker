# 04: Развёртывание и допуск к реальным данным

**What to build:** развернуть дневник на проверенном окружении, доказать восстановимость всей синтетической истории из внешней копии и зафиксировать допуск к первым реальным данным.

**Blocked by:** 01, 02, 03.

**Status:** needs-info

**Type:** task

- [ ] Все блокеры и их транзитивные зависимости завершены. До успешной приёмки используются только синтетические данные; незавершённая проверка VPS/хранилища или неуспешное восстановление запрещают допуск реальных данных.
- [ ] На фактическом VPS проверены единый HTTPS-origin, перенаправление на HTTPS, Host, доверие прокси, закрытый внутренний порт, firewall, запуск без root/отладки, права БД и секретов, системное время и отсутствие личных данных в логах. Релиз запускается через Docker Compose (`back` и `front`), зависимости берутся из lock-файлов; на хосте не требуется Python/Node.js. Проверены `up --wait`, restart-политика и обновление по README.
- [ ] БД находится в постоянном именованном томе `diary_data` на локальном диске вне образа и публичной статики; сертификаты Caddy также сохраняются в томе. `down -v` для сохраняемых данных запрещён. Перезагрузка и смена релиза сохраняют историю; внешние ключи и надёжная фиксация включены. Блокировка, нехватка места и сбой commit не дают частичного успеха.
- [ ] Миграции выполняются явно через `docker compose run --rm back python -m diary.admin --database /data/diary.sqlite3 migrate`. Перед миграцией создаётся проверенный снимок; обновление существующей схемы сохраняет UUID, значения, времена, редакции, удаления и версии. Повтор миграции не создаёт пустую БД. Описано возвращение совместимого кода либо восстановление с учётом новых записей.
- [ ] На рабочем внешнем хранилище выполнена копия во время записи и проверено восстановление по контрольным данным снимка. Установлены и проверены ежедневный запуск в 03:00 по Москве, повтор пропущенного запуска, исключение параллельного запуска, политика семи ежедневных точек и еженедельные проверки восстановления/блоков.
- [ ] Выбранная внешняя точка восстановлена в чистое изолированное окружение только по инструкции и независимо сохранённым реквизитам. Проверены целостность, схема, количества и содержимое всех сущностей, историческая база и границы, сводки, полный экспорт и новый вход; восстановленные сессии отозваны. Рабочая БД остаётся нетронутой.
- [ ] Без секретов записаны дата учения, идентификатор точки, версия приложения, результат и фактическая длительность. Учение повторяется после изменений схемы или механизма резервирования; пределы потери данных и хранения семи точек явно описаны.
- [ ] Пройдены согласованные HTTP- и браузерные сценарии на синтетической истории, проверены конкурентные запросы и работа на объёме, представляющем многолетний дневник; записаны объём и результаты измерений без выдуманного SLA.
- [ ] На реальном iPhone и компьютере проверены вход, десятичная клавиатура, фокус, доступность сохранения, повторы после сети/истечения сессии, правки, база, графики, экспорт и статус копий. Вручную оценены контраст, тёмная тема и удобство после пары дней синтетического использования; результаты и нерешённые проблемы записаны.
- [ ] Итог приёмки явно указывает, разрешён ли запуск с реальными данными. При нерешённых условиях записаны причины отказа; готовность спецификации или прохождение локальных тестов не подменяют эксплуатационный допуск.
