# 01: Личный каталог продуктов и порций

Status: resolved
Type: task
Blocked by: None (can start immediately)

**What to build:** пользователь открывает раздел «Питание» в интерфейсе A и ведёт личный каталог продуктов с именованными порциями: создаёт, ищет, исправляет, архивирует и возвращает карточки.

**Основание:** [спецификация этапа](../spec.md), разделы «Существующие границы и стек», «Каталог и порции», «Числа и калькулятор еды», «API, сохранение и интерфейс», «Testing Decisions». Требования спецификации обязательны в границах этой задачи.

- [x] Пятый раздел доступен в навигации desktop/phone без настройки базы; прежние разделы и данные дневника сохранены. Каталог изначально пуст, поиск по подстроке работает без учёта регистра, включая кириллицу; названия и поиск остаются приватными.
- [x] Карточка содержит название, основу 100 г либо 100 мл и четыре независимых показателя. Неизвестное отличается от известного нуля; точка и запятая принимаются с установленной точностью и пределами. Калории не вычисляются из БЖУ, перевод г ↔ мл не выполняется.
- [x] Пользователь атомарно сохраняет карточку с упорядоченным набором именованных порций с устойчивыми идентификаторами и положительным количеством в единице продукта. Порции можно добавлять, менять и убирать; самостоятельной пищевой ценности у них нет.
- [x] Правка и архивирование проверяют редакцию карточки. Смена единицы требует явных новых значений и нового набора порций либо очистки старого с подтверждением; архив доступен отдельно с возвратом карточки в обычный выбор.
- [x] Сохранение использует атомарные квитанции операций; повтор не создаёт дубликат, иное содержимое с тем же UUID и устаревшая редакция дают конфликт. Ошибки сети и входа сохраняют черновик и удержанный запрос в памяти вкладки; повторное сохранение только явное, личные сведения до входа скрыты.
- [x] Миграции создания каталога и порций работают с пустой и прежней БД, повторный запуск безопасен; прежняя история сохраняется. Обновлены относящиеся к задаче описания API и действующего поведения.
- [x] Пройдены относящиеся к задаче проверки HTTP API на файловой SQLite с настоящими миграциями, доступом, валидацией, конфликтами и откатом без частичной карточки. Desktop/phone Chromium проверяет каталог, кириллицу, формы, переходы и сохранность черновика; интерфейс A доступен с клавиатуры и на ширине 375 px.
