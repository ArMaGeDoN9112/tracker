# 04: Учёт воды и настройка быстрых кнопок

Status: resolved
Type: task
Blocked by: None (can start immediately)

**What to build:** пользователь явно добавляет выпитую воду, видит события и сумму московского дня, исправляет ошибки и настраивает привычные объёмы на всех устройствах.

**Основание:** [спецификация этапа](../spec.md), разделы «Существующие границы и стек», «Вода», «День и сводки питания» в части дня, «API, сохранение и интерфейс», «Testing Decisions». Каталог и приёмы пищи для учёта воды не требуются; используется общий раздел «Питание» в интерфейсе A.

- [x] Вода доступна в дне питания с начальными кнопками 200, 250 и 500 мл и произвольным вводом целых мл в установленном диапазоне. Быстрая кнопка использует текущее серверное время; заднее число и другое время вводятся явно по Москве.
- [x] Каждое намеренное добавление создаёт самостоятельное событие, совпадение объёма и времени не объединяет записи. Повтор неопределённого запроса удерживает прежние UUID и время и не создаёт дубликат.
- [x] Настройки кнопок сохраняются на сервере общими для устройств: упорядоченные уникальные положительные объёмы, включая допустимый пустой набор. Произвольный ввод остаётся доступен. Правка настроек проверяет редакцию, поддерживает безопасный повтор и не меняет историю воды.
- [x] История показывает все неудалённые события выбранного дня, их объём и время в устойчивом порядке. Сумма учитывает только явно внесённую воду; пустой день показывает «Нет записей воды». Продукты в мл не добавляют воду автоматически, запись воды не создаёт еду или калории.
- [x] Доступны правка объёма/времени, перенос, мягкое удаление и отмена строго до 30 секунд по серверу. Обе затронутые дневные суммы актуализируются; общая отмена доступна между разделами.
- [x] Все изменения атомарны с квитанциями; конфликты редакций сохраняют ввод, старые квитанции не отменяют последующие изменения. Черновики и неопределённые запросы переживают переходы и повторный вход в памяти вкладки без автоматического сохранения; поздние ответы не подменяют выбранный день. Соблюдаются общие требования доступа, приватности и доступности.
- [x] Миграции с нуля и с прежней схемы сохраняют дневник, настройки имеют определённые начальное состояние и редакцию. Обновлены API и правила продукта.
- [x] HTTP API на файловой SQLite проверяет пресеты после перезапуска, диапазоны, отдельные добавления против сетевого повтора, гонки, rollback, переносы и границу отмены. Desktop/phone Chromium проходит быстрый и ручной ввод, настройки, исправление и отмену с обновлением суммы и сохранностью черновика.
