# 03: Разовая еда и повтор приёма пищи

Status: resolved
Type: task
Blocked by: 02

**What to build:** пользователь записывает разовую еду без обязательного каталога и веса, смешивает её с продуктами, при необходимости создаёт карточку и повторяет прошлый приём в новом проверяемом черновике.

**Основание:** [спецификация этапа](../spec.md), разделы «Числа и калькулятор еды», «Приём пищи и неизменность прошлых фактов», «Разовая еда и повтор», «API, сохранение и интерфейс», «Testing Decisions». Общие гарантии сохранения и дня из задачи 02 распространяются на новый тип строки.

- [x] Разовая еда требует только непустого названия: количество и четыре показателя необязательны, известный ноль отличим от неизвестного. При известном количестве указаны г или мл. Можно сохранить полностью неизвестную пищевую ценность и смешать разовую еду с продуктами; пустой состав отклоняется.
- [x] При первом сохранении значения относятся ко всей съеденной порции. Для последующей правки количества хранится самостоятельная исходная основа; пропорциональный пересчёт не накапливает округления. При неизвестном исходном количестве новый вес сам по себе не позволяет вычислить ценность.
- [x] «Сохранить как продукт» работает и после записи: показывает пересчёт на 100 г/мл и округление карточки, требует явного сохранения. Без известной основы предлагает ввести фактическое количество исходной порции либо независимо заполнить новую карточку. Отказ не мешает записи и повтору еды; исходный приём не меняется.
- [x] «Повторить» для неудалённого приёма открывает новый черновик с текущими датой и временем сервера в момент открытия, независимо от просматриваемого дня. Время видно и не обновляется скрыто; до явного сохранения новое событие не создаётся, идентификаторы новой записи независимы.
- [x] Повтор копирует порядок, категорию, исторические снимки и количества, допускает изменение состава, времени и количества. Разовая еда без веса переносится как целая порция; для иной порции пользователь явно меняет значения или задаёт достоверную основу.
- [x] Изменённый либо архивный каталог не подменяет данные повтора. Изменение исходного приёма после открытия черновика не переписывает его; сохранение повтора и правка исходного события независимы. Актуальную карточку пользователь выбирает явно.
- [x] Сохранение смешанного состава атомарно; ошибки, конфликты и повтор запроса сохраняют черновик и не создают дубликатов. Дневные расчёты включают новые строки с правильной неполнотой. Обновлены миграции при необходимости, API и действующие правила продукта.
- [x] HTTP API на файловой SQLite проверяет неизвестную основу, точные повторные пересчёты, отдельное создание продукта и независимость событий. Desktop/phone Chromium проходит смешанный приём, создание карточки с предпросмотром, повтор после изменения каталога и отсутствие сохранения до подтверждения формы.

## Answer

20 октября 2026: задача 03 реализована локально. Миграция `007_one_off_meals`
сохраняет прежние строки и добавляет разовую еду с необязательной ценностью/весом
и самостоятельной исходной основой. Смешанные составы используют общую атомарную
запись и точные расчёты. Создание карточки — отдельный явный шаг с предпросмотром
на 100 г/мл, вводом достоверной основы либо независимой новой карточкой.

Повтор получает текущее серверное время и новые UUID строк, копирует исторические
факты в проверяемый черновик и ничего не записывает до подтверждения. Каталог
и последующие изменения источника не подменяют черновик; события независимы.

Проверки: HTTP приёмов/разовой еды — 64 passed; полный backend — 284 passed
(включая локальный restic); полный desktop/phone Chromium — 104 passed.
Mypy, TypeScript и production-сборка успешны. Проверены пять ширин 375–1440 px.
Ревью: Standards — 0, Spec — 0 оставшихся замечаний (1 исправлено).
