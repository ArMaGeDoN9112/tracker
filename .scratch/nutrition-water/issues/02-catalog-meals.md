# 02: Запись и исправление приёмов пищи из каталога

Status: resolved
Type: task
Blocked by: 01

**What to build:** пользователь собирает приём пищи из продуктов каталога, видит пересчитанные показатели, сохраняет его и проверяет либо исправляет историю и итоги московского дня.

**Основание:** [спецификация этапа](../spec.md), разделы «Каталог и порции», «Числа и калькулятор еды», «Приём пищи и неизменность прошлых фактов», «День и сводки питания» в части дня, «API, сохранение и интерфейс», «Testing Decisions». Разовая еда и повтор добавляются задачей 03; сводки периода — задачей 05.

- [x] Форма позволяет найти продукт, выбрать порцию, изменить съеденное количество г/мл и объединить несколько строк общим временем с необязательной категорией. Недостающий продукт создаётся из формы самостоятельным сохранением без потери состава; отмена приёма не удаляет карточку.
- [x] Калькулятор показывает известные БЖУ и калории до сохранения, единицы, основу и пояснение округления. Сервер рассчитывает результат из точных исходных величин; half-up применяется независимо на уровне строки, приёма и дня, а не к сумме экранных округлений. Калории с этикетки сохраняются независимо.
- [x] Сохранённый состав упорядочен и самодостаточен: содержит исторические название, единицу, количество, основу расчёта, показатели и происхождение продукта/порции. Правка или архив каталога не меняют сохранённый приём и уже выбранный черновик; актуальный продукт подставляется только явным новым выбором.
- [x] Пользователь видит все приёмы выбранного московского дня с составом и устойчивым порядком. Итоги отдельно показывают известные и неизвестные вклады каждого показателя, неполноту, известный ноль и отсутствие еды. Заднее число и московские границы дней соблюдаются.
- [x] Доступны правка полного состава, количества, категории и времени, перенос между днями, мягкое удаление и атомарная отмена строго до 30 секунд по серверу. Правка использует сохранённую основу, не меняет каталог и другие приёмы; изменение только категории или состава сохраняет исходное время и его точность.
- [x] Заголовок, все строки и квитанция сохраняются одной транзакцией. Ошибка строки, превышение лимита тела, сбой commit или квитанции не оставляют частичный приём. Повторы, конфликты редакций и старые квитанции соблюдают общие правила; поздний повтор создания не воскрешает удалённое.
- [x] Черновик, конфликт и неопределённый запрос переживают переходы и повторный вход в памяти вкладки. Отмена доступна между разделами без продления срока; поздние ответы старого дня не заменяют текущий. Доступ, приватность, ошибки полей и доступность соответствуют спецификации.
- [x] Миграции сохраняют прежнюю историю; обновлены API и правила продукта. HTTP API на файловой SQLite проверяет расчёты независимыми ожидаемыми значениями, включая две округлённые строки по 0,01 с общим итогом 0,01, исторические снимки, гонки, rollback и отмену на 29999/30000 мс. Desktop/phone Chromium проходит создание из каталога, правку, навигацию и явный повтор после обрыва ответа без дубликата.

## Answer

20 октября 2026: задача 02 реализована локально. Миграция `006_meals`, API приёмов
и московского дня, независимые исторические снимки, точная рациональная арифметика
и half-up на уровне строки/приёма/дня. В интерфейсе A — состав из каталога и порций,
создание карточки без потери состава, калькулятор, история/итоги, правка/перенос,
мягкое удаление и глобальная отмена. Черновик/конфликт/неопределённый запрос
переживают навигацию и повторный вход в памяти вкладки.
