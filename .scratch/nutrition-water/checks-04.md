# Задача 04: вода — проверки

Дата: 20 октября 2026. Только локальные синтетические данные; рабочие тома,
реальные записи, VPS и внешнее хранилище не подключались. Базовый коммит:
`03478b9cb9d05d3ed96d62b479eb2036424ff656`, текущая ветка `master`.

## Объём

Самостоятельные события воды, настройки быстрых кнопок, московский день,
редакции/квитанции, перенос, мягкое удаление и общая отмена. Периоды и экспорт v2,
предметная проверка восстановления питания — задачи 05–06. Существующие
незакоммиченные изменения пользователя в agent docs/roadmap/spec/acceptance
не включены в коммит задачи.

## HTTP API и миграции

Граница: настоящий FastAPI TestClient, файловая SQLite и Alembic. Команда через
Docker Compose с bind mounts актуальных `diary`, `migrations`, `tests`:
`docker compose run --rm ... checks pytest -q tests/test_water.py`.

22 проверки покрывают:

- серверный момент быстрой записи; отдельные намеренные добавления с одинаковым
  временем/объёмом; безопасный повтор и конфликт другого содержимого UUID;
- начальные 200/250/500 и редакцию 1, сохранность настроек после нового экземпляра
  приложения, упорядоченный/пустой набор, уникальность, строгие целые мл;
- минимум 1, максимум 2147483647, сумму выше предела события; отклонение нуля,
  отрицательного, дробного (включая JSON 1.0), строки, boolean, null;
- московские границы и устойчивый порядок при равных моментах; перенос между
  днями, удаление/восстановление сумм; отсутствие еды/калорий от воды и воды от еды;
- stale revisions, гонки одинаковых UUID, конкурирующие edit/delete и настройки;
- rollback при отказе записи квитанции и commit, явный повтор без квитанции;
- серверную границу отмены 29999/30000 мс, остаток срока при повторе и старые
  квитанции, не отменяющие последующее изменение;
- Origin/CSRF, no-store, анонимный доступ, лимит 65536 байт, время со смещением;
- создание с нуля, повтор upgrade и переход с 007 с сохранением диабетического
  дневника, приёмов и действующей сессии.

Обновлены два прежних теста: backup manifest ожидает 008; тест миграции с 006
сравнивает прежние сущности до/после через старые API и читает расширенный день
после upgrade. Первоначальный полный прогон: 304 passed / 2 failed на этих
устаревших ожиданиях; адресный повтор после исправления: 22 passed.
Финальный полный backend-прогон: **306 passed**, 5 предупреждений зависимостей,
326,72 секунды. Проверен настоящий локальный restic в изолированных каталогах.

## Chromium и визуальная проверка

`docker compose run --rm ... e2e npm --prefix frontend run test:e2e -- water.spec.ts`:
14 passed (7 сценариев × desktop/phone). Только настоящий API и синтетическая БД;
перехват используется для задержек/обрывов, успешные данные не подменяются.

- Быстрое/ручное добавление, изменение кнопок, исправление объёма/времени,
  перенос, удаление и отмена из настроек с обновлением суммы и сохранным вводом.
- Потерянный ответ после настоящего commit, навигация/повторный вход без
  автоматического сохранения, повтор точного тела, актуальная история после
  чужого удаления вместо воскрешения старой квитанцией.
- Ошибка поля с aria-invalid и фокусом, подтверждённая операция с ошибкой чтения,
  реальный конфликт редакций воды и настроек, явное сравнение/продолжение ввода.
- Пустые кнопки сохраняют ручной ввод; старый ответ сохранения читает актуальные
  настройки; поздний GET старой редакции не заменяет подтверждённые новые кнопки.
- Поздний ответ старого дня, loading/error/retry, сохранение намеренно пустого
  времени через навигацию и повторный вход.
- Ширины 375/390/768/1280/1440, отсутствие горизонтального переполнения,
  keyboard Tab и фокус, кнопки минимум 44 px. Снимки `acceptance/water-*.png`.

Полный предыдущий прогон: 114 passed до двух добавленных регрессий ревью.
Финальный полный прогон: **118 passed** (desktop/phone Chromium, 3,3 минуты).

новые кнопки; намеренно пустое время восстанавливалось при навигации. Исправлены

## Границы

Экспорт v1 пока не содержит питание/воду. Экспорт v2 и предметное чтение новых
сущностей при verify/restore остаются задаче 06. Прежний полный backend-набор
проверяет настоящий локальный restic на новой схеме, но не заменяет её приёмку.
Safari/реальный iPhone, реальные данные и внешнее хранение не проверялись.
Черновики в памяти вкладки могут потеряться при перезагрузке/закрытии.
