## Область

diary/app.py, security.py, admin.py, db.py, middleware, migrations entrypoint, tests/test_access.py, Docker.

## Работа

Выделить классы входа/выхода, получения/проверки сессии и CSRF, создания аккаунта, сброса пароля и административного запуска миграции. Cookie/Host/Origin/HTTP-заголовки оставить в HTTP-адаптере; Argon2, токены, SQL и Alembic — в infrastructure. Сборку связать явно. Неверный вход фиксирует счётчик до отказа; сброс пароля атомарно отзывает сессии. Токены генерировать криптографически стойко.

## Приёмка

Сохранены лимиты по источнику и логину, сроки и конкуренция, защита приватных маршрутов по умолчанию, CSRF, cookie, безопасные ошибки и скрытый ввод пароля. Старые команды и миграции сохраняют данные.
Проверки запускать через Docker Compose. Сохранять правила code-feedback и инварианты плана.

## Реализация

- `application/access.py`: отдельные `Login`, `Logout`, `GetSession`, `GetCsrf`,
  `CheckCsrf`, Pydantic DTO, порты хранения/криптографии и типизированные отказы.
  Неудачный вход и очистка при лимите фиксируются до исключения; часы и
  криптографический генератор передаются явно через порт.
- `application/admin.py`: `CreateAccount`, `ResetPassword`, `MigrateDatabase`;
  сброс пароля и отзыв всех сессий сохраняются одной транзакцией.
- `infrastructure/access.py`, `security.py`, `database.py`: SQLAlchemy Core,
  SQLite UoW с `BEGIN IMMEDIATE`, Argon2, `secrets.token_urlsafe(32)`, Alembic.
  Сбои преобразуются в безопасный отказ приложения с сохранением причины.
- HTTP-адаптер владеет cookie, Host/Origin, заголовками, middleware и прежними
  ответами. CLI сохраняет скрытый ввод, подтверждение пароля и безопасные ошибки.
  `bootstrap.py` явно связывает сценарии с реализациями портов.
- `diary.app:from_env` и `python -m diary.admin` сохранены. Схема БД, API,
  экспорт и команды не менялись; Docker копирует пакет целиком и не требует
  изменения списка файлов. Инфраструктура backup импортирует новый модуль БД.
- Временные совместимые импорты до этапа 09: `diary/db.py` для старых вызовов
  тестов и `scripts/e2e_server.py`; `diary/security.py` для тестов экспорта.
  `diary/admin.py` сохраняет функции для существующих тестов и e2e setup,
  но сами операции выполняют классы application. Перенесённое ядро мосты не импортирует.
