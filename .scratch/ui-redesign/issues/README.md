существующего интерфейса, включённая в работающий сценарий входа и переходов.

одним циклом реализации и общей итоговой приёмкой, включая их взаимодействие
с готовыми разделами 01–04. Общие стили и интеграционные точки меняются согласованно;
проверки отдельных изменений выполняются по необходимости без повторения всей подготовки.

Общие ограничения: прежние API, SQLite, точность, серверная валидация,
сессии/Origin/CSRF/no-store, приватность и отсутствие постоянного хранения черновиков.
Производственные заглушки из прототипа не используются. Изменений схемы и API нет.
