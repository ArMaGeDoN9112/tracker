# Приёмка 02 — рабочий дневник A

20 октября 2026. Только синтетический аккаунт и одноразовая SQLite из
`scripts.e2e_server`; рабочий том БД не подключался. Исходная реализация: `fae53cf`;
после ревью добавлена связь ошибки пустой записи с группой полей, без смены API.

## Проверки

- TypeScript + production Vite: успешно, 622 модуля. Существующее предупреждение
  о JS chunk >500 kB сохранено; зависимости не добавлялись.
- Полный Playwright Chromium: **48 passed**, проекты desktop и phone.
- Серверные проверки, выполненные основным агентом: `docker compose run --build
  --rm checks` — **189 passed**, 238.16 s; одно существующее предупреждение
  StarletteDeprecationWarning.
- Пять ширин 375/390/768/1280/1440: автоматическая проверка формы первой в узком
  режиме и формы слева в desktop; без горизонтального переполнения, все 25 записей
  и полный длинный комментарий в порядке ответа API. Скриншоты `diary-*.png`.
- Видимые элементы ввода и кнопки дневника имеют высоту >=44 px (фактически общая
  минимальная высота 48 px). Tab с комментария переводит фокус на сохранение;
  кнопка видна выше нижней навигации. Отмена удаления проверена клавишей Enter;
  явный выбор при конфликте сохранён. Золотистый focus-visible виден на снимках.
- При размере текста 200% на 375 px и reduced-motion переполнения нет.
- Отдельные снимки: loading, day-error, empty, field-error, conflict, undo —
  в обоих проектах. Снимки визуально просмотрены для настольного/телефонного
  дневника и конфликта; root также просмотрел 1440 и 375.

## Регрессии через браузер и настоящий HTTP API

Проверены независимый сахар/подколка/комментарий, десятичная запятая и точка,
серверная валидация без потери ввода, пустая запись с ошибкой у группы полей,
историческое неоднозначное московское время, сохранение миллисекунд,
перенос, сравнение конфликтующих редакций, повторный вход с черновиком,
потерянный ответ после настоящего commit и повтор с прежними телом/UUID,
ошибка обновления уже подтверждённой записи, серверная отмена и её срок при
смене разделов, обновление сводок через существующую связь поколений.

Новые проверки дня работают при America/Los_Angeles: соседние календарные дни
через границу года и серверная кнопка «Сегодня» не меняют исторический черновик.
Задержанный ответ старого дня и задержанный ответ «Сегодня» не заменяют новый
выбор. Состояния загрузки, ошибки и пустого дня различаются.

TDD: первый тест падал на отсутствующей кнопке «Следующий день»; затем прошёл.
Следующий падал на отсутствующей подписи «Сохранить запись»; затем прошёл вместе
с проверкой inline-ошибки и подтверждённого сохранения. Проверка delayed Today
падала: выбранное `2029-01-01` заменялось текущим серверным днём; после защиты
поколением запроса прошла. Проверка пустой записи падала на отсутствии доступной
группы с aria-describedby; после минимального исправления прошла, включая
самостоятельное сохранение комментария.

## Воспроизведение

Обычный полный запуск: `docker compose run --build --rm e2e`.
Для быстрой проверки использовался собранный образ `diary-layout-a-impl-e2e`
с read-only bind mounts `frontend/src` и `frontend/e2e`. Финальный запуск:

```powershell
docker run --rm --shm-size=1gb -e DIARY_ACCEPTANCE_DIR=/evidence `
  -v '<checkout>/.scratch/ui-redesign/acceptance-02:/evidence' `
  -v '<checkout>/frontend/e2e:/app/frontend/e2e:ro' `
  -v '<checkout>/frontend/src:/app/frontend/src:ro' `
  diary-layout-a-impl-e2e npm --prefix frontend run test:e2e
```

`DIARY_ACCEPTANCE_DIR` включает только дополнительные снимки синтетических
состояний; обычный запуск по-прежнему не сохраняет скриншоты, видео или трассы.
