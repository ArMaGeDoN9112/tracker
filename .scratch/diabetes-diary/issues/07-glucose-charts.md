# 07: Графики и сводки сахара

**What to build:** пользователь просматривает изменения сахара за неделю, месяц или произвольный период, видит состав сводки и переходит к измерениям выбранного дня.

**Blocked by:** 02.

**Status:** resolved

**Type:** task

- [x] Неделя и месяц означают последние 7 и 30 московских календарных дней с выбранной конечной датой включительно; по умолчанию она сегодня. Произвольный период включает обе даты, подписи показывают фактические границы.
- [x] Сервер считает дневные среднее, минимум, максимум и число измерений из неудалённых записей сахара; подколки, комментарии и база не добавляют измерений. Период и график не ограничиваются первой страницей или последними 30 днями.
- [x] Среднее периода считается по всем измерениям без промежуточного округления дневных средних; отображение half-up до десятых. Для 4,0 и 8,0 в первом дне и 12,0 во втором среднее периода — 8,0, а не 9,0.
- [x] День без измерений имеет число 0 и null для остальных значений: график оставляет разрыв. При одном измерении среднее, минимум и максимум совпадают.
- [x] Recharts показывает согласованные значения; рядом доступна текстовая таблица и переход к исходному дню с клавиатуры. Цвет не является единственным носителем смысла, тёмная тема и мобильный экран сохраняют читаемость.
- [x] После реализации исправлений записей проверяется, что перенос, изменение сахара, удаление и отмена обновляют оба затронутых дня и сводки периода. Наличие этих операций не блокирует начало задачи.
- [x] HTTP-проверки с SQLite подтверждают формулы, московские границы, пустые дни и длинную историю. Браузер проверяет три варианта периода, таблицу, разрыв и переход к дню.

## Answer

Реализованы защищённый `GET /api/glucose-summary` и интерфейс Recharts с дневными средним,
минимумом, максимумом, числом измерений, текстовой таблицей и переходом к исходному дню.
Неделя/месяц считаются сервером как 7/30 календарных дней до выбранной московской даты;
произвольный период включает обе границы. Сводки читают всю неудалённую историю сахара,
сохраняют пустые дни и округляют целочисленные суммы half-up только в итоговом значении.
После создания, изменения, переноса, удаления и отмены интерфейс перечитывает сводку.
Миграция БД не требуется.

Проверки в Docker Compose: 174 HTTP-теста с SQLite (13 новых), mypy, TypeScript и
production-сборка; итоговый полный прогон Playwright — 20/20 desktop/mobile Chromium.
Проверены история 2010–2026 без обрезания, историческое UTC+4 Москвы, полночь,
взвешенное среднее, half-up, пустые дни и правки обоих дней. Браузер проверяет все
варианты периода, реальные разрывы линий, таблицу, переход точкой и клавиатурой,
перенос/удаление/отмену и отсутствие горизонтального переполнения страницы.
Снимки desktop/mobile просмотрены. Обнаруженная браузером ошибка перехода через
предыдущую подсказку исправлена: точки и столбцы используют собственную дату.

Standards: 0 открытых замечаний. Spec: 0 открытых замечаний; оба ревью повторены после
исправления перехода. Один прежний мобильный сценарий временной базы один раз дал
неожиданную базу дня; отдельный запуск и повторный полный набор прошли, причина
единичного сбоя не установлена. Vite сообщает размер общего JS 661 КБ (197 КБ gzip).
Реальный iPhone/Safari и VPS не проверялись.
