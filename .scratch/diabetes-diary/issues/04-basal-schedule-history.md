# 04: Суточное расписание базы и его история

**What to build:** пользователь задаёт суточное расписание базы с выбранного момента, видит историю версий и правильную базу для любого события и начала выбранного дня.

**Blocked by:** 02.

**Status:** resolved

**Type:** task

- [x] Создаётся полная неизменяемая версия расписания: обязательное начало 00:00, уникальные возрастающие минуты в пределах суток, неотрицательные скорости с точностью до сотых. API использует десятичные строки, БД — целые сотые.
- [x] Выбирается последняя версия с началом не позже события и последний начавшийся суточный интервал. На точной границе действует новое значение; последний интервал завершается в следующую московскую полночь.
- [x] Возможны будущая и историческая версии. Вставка действует до следующей версии, уточняет базу уже внесённых событий этого периода и не меняет более раннее время. До первой версии база неизвестна, включая период до её исторического начала.
- [x] Перед сохранением видны начало и затрагиваемый период. История показывает сроки действия; перезапись и удаление сохранённой версии недоступны. Занятое начало даёт конфликт со ссылкой на существующую версию.
- [x] Хронология показывает состояние на начало дня и границы изменений; база событий вычисляется из истории, не копируется в запись. Единицы и подпись «по расписанию» видны рядом со значением, неизвестная база отличается от 0,00.
- [x] Создание защищено сессией, CSRF и атомарной квитанцией операции; повтор после потери ответа не создаёт версию повторно. Схема, API, интерфейс и миграции включают историю без удаления по возрасту.
- [x] HTTP-проверки покрывают валидацию интервалов, полночь, точные границы, будущие и промежуточные исторические версии, неизвестную базу и повторы. Браузер проверяет создание версии и просмотр исторического дня.

## Answer

Реализованы неизменяемые полные версии суточного расписания: интервалы с 00:00, точная проверка сотых и целочисленное хранение. API возвращает историю со сроками действия; занятое начало даёт конфликт со ссылкой на существующую версию. Создание защищено общей сессией/CSRF и атомарной квитанцией в BEGIN IMMEDIATE; безопасны поздние и конкурентные повторы, ошибки сохранения не оставляют частичных данных.

База вычисляется из истории для момента записи, выбранного времени формы и начала московского дня. Будущие и промежуточные исторические версии меняют только свой полуоткрытый период; до первой версии возвращается null, ноль отображается как 0,00 ед/ч. Хронология включает границы изменений, в том числе исторический откат часов; отсутствующая московская полночь не сдвигает минуты интервалов. Интерфейс показывает период до сохранения, историю, единицы и подпись «по расписанию», сохраняет черновик и UUID при неизвестном результате.

Миграция 003 добавляет историю без удаления прежних данных. Проверено обновление со схемы 002, повтор миграции и перезапуск. Полный набор: 102 HTTP-теста (33 новых), 14 сценариев Playwright desktop/mobile Chromium (2 новых запуска), mypy, TypeScript и production-сборка. Ревью Standards и Spec завершено без открытых замечаний. Реальный iPhone/Safari и VPS не проверялись.

Решения и результаты записаны в [карте реализации](../map.md#decisions-so-far).
