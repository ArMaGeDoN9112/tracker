# 09: Резервная копия и восстановление на тестовых данных

**What to build:** владелец получает согласованные зашифрованные копии всей БД, может восстановить выбранную точку и видит состояние резервирования в настройках.

**Blocked by:** 01.

**Status:** resolved

**Type:** task

- [x] Разработка и проверки выполняются на синтетической БД и тестовом restic-репозитории без ожидания рабочего VPS или выбора production-провайдера. Проверки настоящей внешней доставки выполняются на тестовом внешнем хранилище при его доступности; отсутствие такой проверки явно фиксируется до финального допуска.
- [x] Команда создаёт полный согласованный снимок через SQLite Online Backup API во время записи, проверяет целостность и внешние ключи, сохраняет версию схемы/релиза, lock-файлы и сведения для воспроизводимого восстановления. Прямое копирование работающего файла БД не используется.
- [x] Restic шифрует логически полную точку всей истории. Предусмотрен ежедневный запуск в 03:00 по Москве независимым системным планировщиком, повтор пропущенного запуска и защита от одновременных запусков; конкретное подключение на VPS завершается при развёртывании.
- [x] После успешной загрузки и проверки читаемости сохраняются семь последних успешных ежедневных точек: одна на московский день, со стабильной группой независимо от хоста/релиза. Ручные и предмиграционные копии отделены. Ротация и освобождение блоков применяются только после успешной новой копии.
- [x] Проверки с управляемыми датами покрывают восемь ежедневных точек, повтор за день, пропуски, смену хоста и отдельные ручные копии. Недоступное хранилище, неверные реквизиты, нехватка места и прерванная загрузка не объявляются успехом и не уничтожают старые точки.
- [x] Настройки показывают время последней успешной внешней копии, результат проверки восстановления и ошибку последнего запуска без секретов. Сбой и отсутствие успешной копии более 26 часов заметны; локальный тестовый репозиторий не выдаётся за подтверждённую внешнюю копию.
- [x] Инструкция восстановления требует остановить запись, сохранить доступное текущее состояние, выбрать совместимый релиз, восстановить в новое место, проверить и затем переключить приложение. Восстановленные сессии отзываются; автоматического уничтожения новых записей при откате нет.
- [x] Описано отдельное хранение ключа restic и реквизитов внешнего хранилища у владельца. Секреты не попадают в логи/репозиторий; нужные конфигурационные секреты входят только в зашифрованную копию. Восстановление сверяется с контрольными данными снимка, а не более поздней живой БД; последующие схемы также охватываются проверками по мере появления.

## Answer

Реализованы `python -m diary.backup` (backup/restore/verify), отдельный Compose-образ
и шаблоны systemd для 03:00 МСК и недельной проверки. Online Backup API создаёт
полную SQLite во время записи; integrity/FK, SHA-256 manifest, версия схемы/релиза,
lock-файлы, backend/миграции и приватная конфигурация сохраняются в зашифрованном restic.
Обратное скачивание и проверка обязательны до снятия pending и ротации. Стабильная
группа diary-v1 и host diary сохраняют семь последних успешных московских дней,
manual/premigration отделены. flock на общем томе исключает параллельные команды.

Восстановление допускается только в новый каталог; сверяется снимок, затем отзываются
сессии. Рабочая БД не переключается автоматически. Недельная команда читает все блоки
репозитория и проверяет восстановленные данные сериализаторами приложения. Настройки
показывают внешний/локальный успех отдельно, проверку, ошибки и просрочку 26 часов.
Инструкция сохранения текущих данных, ключей и переключения — [docs/backup.md](../../../docs/backup.md).

Проверки в Docker Compose: 189 backend/эксплуатационных тестов (8 новых), mypy,
TypeScript/production-сборка, 24 браузерных сценария desktop/mobile Chromium.
Проверены все текущие сущности схемы 004_temporary_basal, удаления, историческая база,
сводки и экспорт, старые cookie/новый вход, конкурентная запись, восемь ежедневных
точек, повтор, московская полночь, пропуски, смена окружения хоста/релиза, ручная копия,
неверный ключ/недоступный репозиторий, смоделированные ошибки загрузки (включая код
прерывания/нехватки места), повреждённое обратное скачивание и блокировка второго запуска.
Отдельный smoke backup/verify прошёл в эксплуатационном образе от UID 10001 без рабочих
томов. Прежний браузерный селектор конфликта уточнён из-за дополнительного предупреждения.

Standards: 0 замечаний. Spec: 0 замечаний; независимое ревью выполнено относительно
35e7d3bbede5317c94672b3bafd405be705cc459.

Внешнее тестовое хранилище недоступно: настоящая внешняя доставка **не проверена**.
Настройка/перезапуск таймеров, права на VPS, реальные сбои сети/диска, независимый доступ
к ключам и полное внешнее учение остаются обязательными до допуска реальных данных.
Реальный iPhone/Safari не проверялся. Одна попытка сборки front получила TLS-таймаут
Docker Hub; TypeScript и production-сборка успешно выполнены в имеющемся Compose e2e-образе.
