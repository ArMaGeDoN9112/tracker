# 09: Резервная копия и восстановление на тестовых данных

**What to build:** владелец получает согласованные зашифрованные копии всей БД, может восстановить выбранную точку и видит состояние резервирования в настройках.

**Blocked by:** 01.

**Status:** claimed

**Type:** task

- [ ] Разработка и проверки выполняются на синтетической БД и тестовом restic-репозитории без ожидания рабочего VPS или выбора production-провайдера. Проверки настоящей внешней доставки выполняются на тестовом внешнем хранилище при его доступности; отсутствие такой проверки явно фиксируется до финального допуска.
- [ ] Команда создаёт полный согласованный снимок через SQLite Online Backup API во время записи, проверяет целостность и внешние ключи, сохраняет версию схемы/релиза, lock-файлы и сведения для воспроизводимого восстановления. Прямое копирование работающего файла БД не используется.
- [ ] Restic шифрует логически полную точку всей истории. Предусмотрен ежедневный запуск в 03:00 по Москве независимым системным планировщиком, повтор пропущенного запуска и защита от одновременных запусков; конкретное подключение на VPS завершается при развёртывании.
- [ ] После успешной загрузки и проверки читаемости сохраняются семь последних успешных ежедневных точек: одна на московский день, со стабильной группой независимо от хоста/релиза. Ручные и предмиграционные копии отделены. Ротация и освобождение блоков применяются только после успешной новой копии.
- [ ] Проверки с управляемыми датами покрывают восемь ежедневных точек, повтор за день, пропуски, смену хоста и отдельные ручные копии. Недоступное хранилище, неверные реквизиты, нехватка места и прерванная загрузка не объявляются успехом и не уничтожают старые точки.
- [ ] Настройки показывают время последней успешной внешней копии, результат проверки восстановления и ошибку последнего запуска без секретов. Сбой и отсутствие успешной копии более 26 часов заметны; локальный тестовый репозиторий не выдаётся за подтверждённую внешнюю копию.
- [ ] Инструкция восстановления требует остановить запись, сохранить доступное текущее состояние, выбрать совместимый релиз, восстановить в новое место, проверить и затем переключить приложение. Восстановленные сессии отзываются; автоматического уничтожения новых записей при откате нет.
- [ ] Описано отдельное хранение ключа restic и реквизитов внешнего хранилища у владельца. Секреты не попадают в логи/репозиторий; нужные конфигурационные секреты входят только в зашифрованную копию. Восстановление сверяется с контрольными данными снимка, а не более поздней живой БД; последующие схемы также охватываются проверками по мере появления.
