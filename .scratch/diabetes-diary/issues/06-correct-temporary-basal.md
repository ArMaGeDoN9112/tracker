# 06: Исправление и завершение временной базы

**What to build:** пользователь исправляет временную базу, завершает её раньше, корректирует окончание задним числом или удаляет запись с возможностью отмены и видит изменившийся период истории.

**Blocked by:** 05.

**Status:** resolved

**Type:** task

- [x] Доступны редактирование начала и процента, досрочное завершение и исправление заданного окончания задним числом. Окончание раньше начала отклоняется; равенство означает нулевой период. Исходная длительность сохраняется.
- [x] До подтверждения показан затрагиваемый период. Изменение начала, окончания или удаление атомарно пересчитывает эффективные границы соседей, не сохраняя искусственно обрезанные заданные окончания.
- [x] Удаление мягкое; без удалённой базы действует расписание либо другая временная база по правилам истории. Отмена в течение 30 секунд по серверному времени восстанавливает действие; конфликт занятого начала объясняется без перезаписи.
- [x] Изменение, удаление и восстановление требуют актуальной редакции и UUID операции. Проверка редакции, квитанция и все изменения атомарны; повтор безопасен, конфликт сохраняет пользовательский ввод для сравнения.
- [x] Хронология и база событий обновляются только для затронутого периода; после окончания применяется обычное расписание без фоновой задачи. Удалённые сущности остаются для экспорта и резервирования.
- [x] HTTP-проверки покрывают исторические правки, соседние границы, удаление B и отмену, конфликт начала и редакции, гонки и границу отмены. Браузер проверяет завершение задним числом и видимость затронутого периода; миграции сохраняют всю историю.

## Answer

Реализованы правка начала/процента/заданного окончания, досрочное завершение, мягкое удаление и отмена строго до 30 секунд по серверному времени. Исходная длительность и время создания сохраняются; соседние эффективные границы вычисляются из истории без сохранённого обрезания. Все изменения и квитанции атомарны в BEGIN IMMEDIATE, проверяют редакцию и занятость начала. Существующая схема 004 достаточна; история, удаления и квитанции сохраняются после migrate и перезапуска.

Интерфейс показывает период до подтверждения, удерживает исходный запрос после потери ответа и сохраняет черновик при конфликте. История, день и база формы обновляются после квитанции. Повтор удаления сверяет текущее состояние: восстановленная другим устройством запись не получает устаревшую кнопку отмены.

Проверки в Docker Compose: 161 HTTP-тест (32 новых), 18 браузерных сценариев desktop/mobile Chromium, mypy и TypeScript/Vite. Проверены исторические переносы через соседей, нулевой период, точная граница отмены, конфликты, гонки изменения/восстановления/создания и откат при сбоях записи/квитанции/commit. Ревью Standards и Spec завершено; найденное замечание об устаревшей отмене исправлено с браузерной регрессией. Реальный iPhone/Safari и VPS не проверялись.
